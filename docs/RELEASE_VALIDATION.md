## 镜像和证明材料的验证范围

既有部署已使用本地 AMD64 应用镜像完成一次保留数据升级。升级前备份、原镜像与回退配置均保留在维护者私有备份中，没有删除旧卷或把业务数据放进发行目录。镜像、脚本或源码候选更新后，按实际变更重新执行对应验证；历史快照的结果不自动代表新导出或发布结果。

本地双架构 OCI 导出已验证可运行镜像、blob 校验、SPDX SBOM 与 SLSA provenance。最终镜像摘要及其源码对应关系应按实际发布记录、提交和 OCI 标签核对，不把本地导出当作 GHCR 拉取成功的证明。清单中的证明材料与可运行镜像分别检查，不把证明材料的 `unknown/unknown` 平台当作额外运行架构。

## 备份帮助镜像修复的针对性验证

旧后端容器仍运行，但它记录的镜像已无法用于启动新的归档帮助进程，原备份因此报 `No such image` 和 exit 125。修复后的备份入口默认保留当前容器镜像选择；需要替代时，只接受用户显式指定、已安装且经核对兼容的项目后端镜像。镜像存在性、平台和实际 CLI 探针在创建备份目录、暂停服务或挂载业务卷前执行，后续固定使用同一不可变镜像 ID，不自动下载。

PowerShell 5.1 的 9 项与 Bash 5.3 的 12 项是 Docker 调用协议的 mock 回归及相关语法检查，覆盖缺镜像、错误平台、探针失败、缺命令和禁止静默回退等门禁。另有真实 Docker 的缺失镜像诊断，以及已验证兼容后端镜像在禁网、只读、非 root 条件下的 CLI 探针；这些探针不挂业务卷，也不启动业务应用。

上述协议测试与独立 CLI 探针分别限定其验证范围。后续已通过公共备份入口显式选择经核对兼容的本地后端帮助镜像，真实归档 41 个文件，并在原三个数据卷上完成最终前后端镜像重建。重建前后 24 张业务状态表对比一致，3 项服务密文摘要和主密钥 SHA256 相同；另外核对的 117 个业务文件哈希全部匹配，两份成片的 SHA256、完整 HTTP 200 与 Range 206 返回保持，主 StudioRun 仍为 completed。

这次新增证据覆盖真实备份和同卷重建，恢复的验证范围仍以表中独立测试为准。Bash 5.3 测试不代表 Mac 实机或其默认 Bash 已验证；Mac 实机状态仍为 BLOCKED。具体备份用法见 [Docker 发布与维护教程](DOCKER_RELEASE_GUIDE_ZH.md)。

## 主工作台实测与帧边界

首次关键画面的产品杯型有偏差。通过主工作台提交文字修改后，程序修订出符合直筒无把杯要求的关键画面，再调用真实 H3 生成视频。随后在主界面保留审核版本的请求返回 HTTP 200，合成请求返回 HTTP 202，后台最终生成真实 MP4；StudioRun 完成且没有异常节点。

源视频与审核版本的视频轨均为 56 帧、2.333333 秒，原文件保留。合成保留完整音轨，并按 24fps 输出帧边界补齐；最终新文件为 **57 帧、2.375 秒**，音轨为 AAC 48kHz、2.375 秒。原片规格与成片规格分别记录，不把原片的 56 帧作为最终文件帧数。

审核版与最终 MP4 已通过浏览器实际播放：报告的播放总长分别为 2.336 秒与 2.375 秒，均到达 `ended=true`、`readyState=4` 且 `error=null`。最终下载文件还经过完整解码，错误数为 0。本项证明主程序的修改、生成、审核、合成和播放链路；后续镜像切换的数据保留性仍按对应升级或持久化测试的独立证据判断。

## 画面与模型边界

测试图像与视频是真实模型输出，使用本次新建的中性杯子内容。技术审核不等于用户电影观感审核：模型在“固定机位”指令下产生了推近，已记录为画面遵循偏差；音频完整解码，但未审核其语义。未制造电影质量分数，也未把缩放输出称作原生高清或 AI 超分。

ComfyUI、GPU 推理和模型权重独立部署，不在通用 CPU 镜像中。模型与服务的可用性取决于用户另外配置的实际端点、硬件、权限及服务条款。
