# 从 Word 到 MP4：完整使用教程

先完成对应系统的 [Windows](INSTALL_WINDOWS.md) 或 [Mac](INSTALL_MACOS.md) 安装。默认网址为 `http://127.0.0.1:8080`。本教程从空白安装开始；应用不会附送维护者的人物、产品、声音、项目或模型账号。

主导航依次为 **项目工作台、剧本生成、脚本与分镜、成片审核、合成成片、系统设置**。三个制作页面及返回工作台时保持当前项目；页面内换项目后，地址栏也会同步，刷新仍打开该项目。原“审片与成片”“视频制作”重复页面已移除，旧地址兼容跳转。

## 1. 先把服务配置好

打开左侧**系统设置**，直接查看服务档案与制作画质。先决定这次制作所需的用途：

| 用途 | 何时需要 | 应准备什么 |
| --- | --- | --- |
| 语言、剧本或理解 | 自动创作、结构化解析或素材理解 | 应用支持的语言/视觉模型服务 |
| 图像 | 生成角色、场景、关键画面 | 支持本次参考图数量与模式的图像服务 |
| 视频 | 把镜头输入生成为真实视频 | 支持该协议、模型、画幅、时长和参考方式的视频服务 |
| 配音 | 独立生成对白/旁白 | 可用的 TTS 服务；参考式模型还需合格的授权声音参考 |
| 画质 | 选择超分等后处理时 | 与处理方式、目标分辨率及画幅匹配且已经验证的能力 |
| FFmpeg | 探测、媒体处理与合成 | 通用镜像已包含，不需要宿主机另装 |

新增或编辑档案时，先选用途、服务类型和实际协议，再填地址、模型及凭据。保存后点连接测试，核对反馈的模型能力与限制。使用自己的 API Key，不在聊天、截图、GitHub Issue 或源码中粘贴。

**不能任意替换域名就认为所有供应商都兼容。** 视频通常是提交任务、查询状态、下载文件的异步协议；普通聊天接口或模型列表不能代替它。第三方中转商更换路由后，应按其文档选择已实现的适配器，再做短镜头实测。供应商生成可能收费，连接测试成功不代表真实生成免费或必然成功。

本地模型下载完成后还要启动适用的推理服务。Context-IR 的安装、模型来源校验和 8788 节点入口见 [本地推理节点教程](local-inference.md)。Docker 里不能执行 Windows 的 `.exe`、盘符路径或原生 GPU 启动器。

本地三档视频档案选择“视频生成 → 本地 / 私有 ComfyUI → Context-IR 三档：Fast 4 / Quality 20 / Quality 30”。同机 Docker Desktop 用 `http://host.docker.internal:8788`，另一台自有 GPU 主机用真实私网地址；勾选“确认这是我管理的本地模型服务”，保存后测试连接，无需修改 `.env`。确认只作用于该档案的精确服务地址；HTTP 不适用于任意云端供应商。语音和口型的原生 CLI 也不自动支持通用 HTTP 远程调用。

## 2. 取得当前 Word 模板

在**项目工作台**的 Word 导入区域点击**下载 Word 模板**或**下载完整示例**。当前空白模板是 [剧本模板.docx](templates/剧本模板.docx)，完整示例为 [剧本导入示例.docx](templates/剧本导入示例.docx)。旧的 `剧本导入模板.docx` 保留供历史兼容；新建剧本使用当前模板，不混用早期截图或其他软件的模板。

填写时保留模板的标题层级、表格列名和字段结构：

- 写清项目目标、总体时长、画幅和画面风格。现实电影效果应描述实际材质、光源、空间和可执行摄影，避免让模型同时完成互相矛盾的风格。
- 给人物使用稳定且唯一的身份名或编号，同一人物在所有镜头保持一致；写外形、服装和连续性信息，区分谁说话、谁拿什么、谁在画面哪一侧。
- 场景描述写空间、材料、陈设、天气与光照；具体人物动作放在镜头表演中。
- 每镜写可完成的动作、摄影、持续时间、对白/旁白和声音要求。一个短镜头避免堆积多次复杂动作。
- 固定产品与道具写与图库一致的名称，并说明出现镜头、包装版本、朝向、握持关系和必须保持的外观。
- 明确需要独立 TTS、视频原生声音，还是无对白/仅环境音；不要把备注性前缀混进要朗读的正文。

Word 文字不能自动提供真实照片、音频文件或模型权限。需要固定外观和克隆声音时，仍需在项目中准备相应素材并确认使用授权。

## 3. 导入或先生成剧本

有 Word 时，在项目工作台选择文档上传，等解析结束。不要立即跳过检查：核对人物对应、场景、镜头顺序、时长、画幅、对白说话人和待确认项。页面提供的歧义或输入修正应先完成，避免错误扩散到昂贵的生成阶段。

没有剧本时，可以在**剧本生成中心**填写创作要求，按当前界面选择文字、图片或其他已支持素材作为输入。生成结构化剧本后先阅读审核，再导出 Word。需要调整导出时，可以使用已保存的结构化结果导出新 Word 版本，不必重复调用创作模型。选择审核后建项时，检查项目名称和即将使用的文档版本。

批量产品创作时，区分“一个产品多张照片”和“多个独立产品”；不要把不同包装误认为同一个物品。对模型从图片中推断的材质、规格、卖点和动作进行人工核对。

## 4. 人物、声音与固定产品准备

### 人物参考（可选）

在项目的角色设置中，为需要固定面容的人物上传合适的参考图或选择现有人物资产。人物标准脸与衍生素材要保持同一身份、版本和服装连续性。图片上传成功不等于已经通过外观审核；需要审核的素材按页面逐项确认后才能用于后续步骤。

多人镜头应写清每个人的站位、动作和物品归属，不要只给模型“二人对话”这样模糊的要求。准备参考图前查看图像和视频服务的实际参考预算；多个服务的数量上限可能不同。

### 开始制作前配置声音

有独立 TTS 要求时，在项目开始制作前的声音准备区配置人物声音，上传或选择已授权的参考音频，并填写需要的参考文本/语种等信息。参考音频应清晰、单一说话人、背景干扰少，时长和格式符合所选模型要求。

CosyVoice、IndexTTS 等参考式语音模式不能仅凭 Word 上写“低沉男声”自动产生一个已批准的克隆样本；是否支持描述生成声音、预置音色或参考克隆，取决于实际服务能力。Windows 原生 TTS 安装不等于容器内已安装该服务。

没有对白且不需要独立配音时，明确采用无配音/环境音路径；需要视频模型原生声音时明确选择该路径，避免给不需要的独立 TTS 任务配置空槽位。需要 TTS 但没有参考时，应补齐资料或改变声音策略，再开始制作。

### 固定产品／道具图（可选）

入口在**项目工作台 → 角色设置 → 人物角色参考图下方的固定产品／道具参考图**。没有固定实物时留空即可。

1. 填写与剧本一致的产品或道具名称，批量选择照片，点击**上传并保存到图库**；也可从已有产品图库选择。
2. 同一产品的多角度图放在同一条记录；不同产品、包装语言或外观版本分开保存。不要混用多个盒面版本。
3. 检查对应分镜的绑定和可见状态。图库保存不等于所有分镜已绑定，更不等于模型已实际收到这些图片。
4. 参考预算冲突时查看任务说明与修复入口。程序需要在真实能力内安排参考；不能静默丢掉产品图或把“文字提到产品”冒充实际图像一致性。

生产前实际查看选中的图、角色、说话人与产品，再点击开始。

## 5. 制作画质和模型路由

系统设置保存默认制作画质；项目可以保存自己的配置。核对目标画幅、输出尺寸、质量模式和处理方式。普通缩放、Real-ESRGAN 与 SeedVR2 是不同处理，不能只改服务路由而仍保留另一种处理方式。

在**项目工作台 → 第二步制作设置 → 实际镜头画幅**，勾选要修改的镜头，选择 **16:9 横向、9:16 竖向或 1:1 方形**，点击**保存选中镜头画幅**。这会保存实际镜头方向；只改输出画幅或提示词中的“竖屏”不能替代此操作。全部镜头方向相同时，页面同步输出画幅草稿，核对后点击**保存项目制作设置**，再开始制作。

| 输出规格 | 16:9 横屏 | 9:16 竖屏 |
| --- | --- | --- |
| 720p | 1280×720 | 720×1280 |
| 1080p | 1920×1080 | 1080×1920 |
| 2K / QHD | 2560×1440 | 1440×2560 |
| 4K UHD | 3840×2160 | 2160×3840 |

这些是后期输出尺寸。页面分别显示当前处理方式对每个组合的验证状态；新增竖屏选项不会自动开放未经验证的 SeedVR2 或其他 AI 处理组合。1:1 输出边长依次为 720、1080、1440、2160 像素。

有正在执行或结果未知的模型任务时，先核对并等待任务结束；暂停编排不能取消已提交的模型任务。暂停后修改画幅，使用工作台的**开始／增量续作**，旧编排保留原快照。旧文件不会裁切或覆盖；已批准镜头修改画幅后需重新制作与审核。出现修订冲突时重新读取并检查镜头，不要重复提交旧修订。

本地 H3 新任务按已保存模式选择真实工作流：**Fast＝SMD4 Fast＋4step LoRA／4 步，标准＝Quality／20 步，高质量＝Quality／30 步**。三档都走 Context-IR 编译，实际输入可以是文字、图片、参考视频及其组合。参考视频默认提供动作和摄影结构，不能据此替换人物或产品身份。任务快照记录实际工作流、步数、服务和素材哈希；改档仅影响后续尚未派发任务。

需要 SeedVR2 时，必须同时保存 SeedVR2 处理方式并验证**确切目标分辨率与画幅**。某个横屏档位已验证，不代表所有竖屏、4K 或其他档位都可用。现有 Windows 原生环境的 720p 横屏和 1080p 竖屏测试不能作为 Docker 或 Mac 上同一能力的证明。通用镜像不含对应模型运行环境。

已经开始制作的项目，在支持的界面使用**保存并应用到未派发画质任务**。程序保留已接收/执行的任务及源视频，不会把中途改配置当作重写全部已生成结果。若界面提示版本冲突，刷新读取最新配置后再处理。

原生生成分辨率与后期输出规格应分开理解。放大成 1080p 或 4K 不表示模型原生生成了该分辨率，也不能保证材质和细节达到真实电影效果。

## 6. 启动自动化并读懂状态

核对输入后点击工作台的开始制作或继续制作。后端编排任务，而不是浏览器假装进度；关闭网页不等于取消供应商正在运行的任务。

- 等待、排队、执行中：读取真实任务状态，需生成时等待外部服务。
- 等待人工审核：查看人物、场景、关键画面或视频，按实际结果批准或要求修改。
- 等待处理异常/失败：展开真实错误，检查缺少的配置、能力或输入，修正后从程序的修复/重试入口继续。
- 提交结果未知：先核对供应商任务和账单，不要反复提交同一请求。

不要通过刷新页面、多开网页或直接改数据库来跳过状态约束。若一键修复仍返回同一错误，应保存错误码、请求 ID 和可复现步骤反馈。

### 对白音频超过镜头长度

在“需要处理的异常”中的音频超长卡片核对实际时长，再选择处理方式：

- **延长镜头**：填写新时长，程序重新生成本镜视频，沿用已完成配音，再接续混音和画质处理。
- **缩短台词**：选择具体台词并修改本轮配音文字，重新生成该句声音；原视频和原剧本保留。
- **调整语速**：选择该句服务实际支持的速度和语言，重新生成配音；原视频保留。

点击“预览处理影响”，核对后点击“确认并开始重新处理”。程序会自动接续所列节点，原始文件和历史任务保留。新音频仍超长时再次提示选择，不静默截断。书写字数不能直接决定说话时长；以新音频实测为准。若需要以后新建制作也使用短台词，请同步修改原剧本或 Word。

语言和语速能力按所选句子的实际适配器显示，部分服务没有独立语言参数。英文台词使用 IndexTTS 2.5 时可明确选择 EN。原生 CLI 仍需适用环境，普通 Docker 镜像不会因此自动拥有 Windows TTS 模型。详见 [对白超长处理](对白超长处理.md)。

## 7. 视频审核与文字修改

在成片审核中实际播放每条视频，检查人物身份、产品外观、动作连续性、声音、对白说话人、画幅和时长。技术检测只能证明可解码等属性，不能替代外观、表演和对白审核。

提交文字修改时，描述具体要改变的内容和需要保持的内容。使用完整提示词编辑区域查看并删改当前镜头输入，保存后再提交真实生成；不要只在备注中写“减少字数”却仍提交原来的长输入。

本地视频提示词没有应用层统一字数上限，仍受模型上下文和运行资源限制；云端按实际供应商限制检查，超过时在可编辑输入处删减。系统不应静默截断剧本、身份或参考信息。

改画幅还需要实际生成尺寸匹配。只把文案中的“横屏”改为“竖屏”并不能转换真实源文件，应按[制作画质和模型路由](#5-制作画质和模型路由)先保存实际镜头画幅，再提交新版本。

## 8. 合成最终 MP4

在合成工作台选择本项目已批准的真实视频版本，排序，按界面支持的方式设置剪辑与音频。删除一个片段后，检查剩余轨道与选择的版本，再点击渲染最终 MP4。

渲染完成后下载并实际播放，检查顺序、接点、总时长、画幅和音轨。原片比计划略长时，保留原片、裁剪或其他处理必须使用明确的编辑选择，不能把供应商实际帧数自动当成目标帧数。

下载到个人磁盘便于分享，但不是应用全部业务数据的备份。角色库、源片、剧本和任务等仍在 Docker 数据卷中。

## 9. 日常运行命令

在包含 `compose.yaml` 的目录运行：

| 命令 | 用途 |
| --- | --- |
| `docker compose up -d` | 构建当前下载的源码并启动，保留数据卷；升级前先更新源码并备份 |
| `docker compose start` | 启动已经存在且已停止的容器，不重新构建 |
| `docker compose ps` | 看容器是否运行、健康状态和映射端口 |
| `docker compose logs -f` | 持续看日志；按 Ctrl+C 退出日志显示，不会停止容器 |
| `docker compose logs --tail=100 backend` | 只看后台最近日志，便于排错 |
| `docker compose restart` | 重新启动当前容器，不重新构建源码；有生成任务时先核对任务状态 |
| `docker compose stop` | 暂停服务，保留容器和数据 |
| `docker compose down` | 移除本项目容器和网络，保留命名卷 |

升级、备份和恢复见 [Docker 发布与维护教程](DOCKER_RELEASE_GUIDE_ZH.md)。

## 10. 判断这次是否真的成功

第一次测试建议用一个人物、一个场景、一个短镜头，按以下结果判断：剧本解析正确 → 所需素材已准备 → 模型任务真的提交 → 供应商返回终态 → 视频已下载到应用 → 能播放 → 人工审核 → MP4 合成可播放 → 重启后记录与文件还在。

网页能打开、测试连接通过、进度到 100% 或文件扩展名是 `.mp4`，都不能单独证明完整生产成功。遇到问题按 [故障排查](TROUBLESHOOTING_ZH.md) 留下脱敏证据。
