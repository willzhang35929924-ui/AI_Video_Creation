# 故障排查

先保留数据再排查。不要通过删数据库、主密钥、Docker 卷或重复付费提交来试错。所有 Docker 命令在实际安装的 Compose 目录执行；使用非默认项目名时，确保当前终端选择的是正确项目。

## 先取得最小诊断

```bash
docker version
docker compose version
docker compose ps
docker compose images
docker compose logs --tail=100 backend frontend
docker compose exec backend python -m app.container_entrypoint doctor
```

网页健康信息：`http://127.0.0.1:8080/api/health/runtime`，端口以自己的配置为准。提交日志前遮住密钥、签名 URL、用户名、私人文件名、脚本内容和素材。不要直接提交 `.env`、备份、数据库或全量 `docker inspect`。

## Docker 与启动问题

| 现象 | 检查与处理 |
| --- | --- |
| 找不到 `docker` 命令 | 安装官方 Docker Desktop，关闭旧终端后重新打开；核对安装是否完成 |
| 无法连接 Docker 引擎 | 打开 Docker Desktop 并等待引擎运行；Windows 检查 WSL 2、虚拟化与 Linux 容器模式 |
| 提示找不到 Compose 文件 | 当前目录应能看见 `compose.yaml`，不要在 ZIP 中直接运行，先完整解压 |
| 镜像引用为空或自定义地址错误 | 当前 Compose 已含确认的目标镜像默认值；检查是否用了旧配置，或被自己的 `.env` 覆盖。不要猜测镜像地址；公开发布尚未完成时，开发者可用 `compose.dev.yaml` 验证源码 |
| GHCR 403、denied、unauthorized | 确认实际镜像地址和标签。公开发行镜像应可匿名拉取，维护者需检查 Package 可见性与仓库关联，不能把每个用户申请私人 Token 当作正式安装步骤 |
| 下载超时、DNS 或 TLS 错误 | 检查 Docker Desktop 网络/代理、企业证书和磁盘空间；按官方配置代理，保留 TLS 校验，不把密钥改写进 URL |
| `no matching manifest` | 检查 Docker 架构和发布镜像清单。Apple Silicon 需要 ARM64；报告缺失的架构，不直接强制 AMD64 并宣称跨平台完成 |
| 端口被占用 | 用 `.env` 修改 `WEB_PORT` 后重新 `up -d`；同一端口不能被旧安装和新测试同时绑定 |
| 容器反复退出 | 看后端启动日志和健康检查，检查只读文件系统下的数据卷写权限、主密钥、配置与迁移错误；不要直接删除卷 |
| 前端 502 或暂时无法加载 | 后端可能还在迁移、启动失败或请求返回业务错误；查看 backend 日志及页面错误码，请勿把所有 API 错误都当作前端静态页面问题 |

Docker 安装与当前平台限制以 [Windows 官方说明](https://docs.docker.com/desktop/setup/install/windows-install/) 和 [Mac 官方说明](https://docs.docker.com/desktop/setup/install/mac-install/) 为准。

## GitHub 登录与推送授权

GitHub 网页登录、VS Code/Git 的推送授权、Actions 发布权限和 GHCR 公开访问分别检查。网页能登录不保证其他步骤已有权限；不要凭“登录失败”猜测具体原因。先记录实际错误，再按 [VS Code 教程的登录说明](VSCODE_GITHUB_GUIDE_ZH.md) 走官方浏览器授权流程。HTTPS Git 不使用账户密码，网页登录支持的方式以 [GitHub 官方认证说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/about-authentication-to-github) 为准。不要在聊天或 Issue 中发送密码、Token 或验证码。

如果该账号不支持网页密码登录，使用它原先已配置的 Google、Apple 或 passkey 等可用方式，并按页面要求完成验证；不要反复尝试不适用的密码入口，也不要从报错猜测账号当初的注册方式。登录验证与账号恢复由账号持有人按 GitHub 官方流程处理，本教程不自动执行账号恢复或更改登录设置。

只有推送工作流文件时实际报告缺少 `workflow` 权限，才按该错误补充授权：维护者已有 CLI 登录可运行 `gh auth refresh --hostname github.com --scopes workflow`；首次登录使用 `gh auth login --hostname github.com --git-protocol https --web --scopes workflow`。授权成功后再检查推送结果，不把认证失败误判成 Docker 或模型故障。

## 数据、迁移与备份问题

**网页突然变成空白新项目列表。** 先检查当前目录、`.env`、`COMPOSE_PROJECT_NAME`、Docker context 与卷：

```bash
docker compose ls
docker volume ls
docker context show
```

换项目名或 Docker 数据盘可能连接了另一套卷。原来的卷可能仍在，不要创建历史数据的“替代记录”或覆盖数据库。

**数据库有表但没有迁移版本。** 后端会拒绝自动重建。先做原数据副本，确认旧应用版本与表结构，再决定兼容迁移。不要手动删表、随意标记 Alembic 为最新或复制新空数据库覆盖。

**服务档案保存过，升级后无法解密。** 检查 `/app/data/.secrets/master.key` 是否与数据库来自同一备份。仅恢复数据库或单独换主密钥无法解密旧数据。用完整备份恢复到空卷，不要通过删除主密钥排错。

**备份提示还有任务。** 等待生成任务进入安全状态；从应用支持的控制入口处理任务后再备份。供应商已接受的任务不一定能取消，关闭网页也不能取消云端收费任务。Docker 备份脚本会拒绝排队/运行中的任务，不强制终止生产。

**备份报 `No such image`、exit 125 或帮助镜像不可用。** 容器能继续运行，不保证其记录的旧镜像仍可供新的帮助容器使用。新版备份脚本会在创建备份目录、停服务或挂业务卷前检查本地镜像与实际 CLI，失败时明确拒绝，不会自动拉取或静默换镜像。核对本机现有的兼容项目后端镜像后，PowerShell 备份可用 `-HelperImage`，Bash 备份可用 `--helper-image` 或 `BACKUP_HELPER_IMAGE` 显式指定。它们不是任意 Python 或其他应用镜像的兼容承诺；镜像需匹配项目的数据库结构、归档 CLI 和实际运行平台。完整示例见 [备份帮助镜像说明](DOCKER_RELEASE_GUIDE_ZH.md)。不要通过删容器、卷或密钥解决这个错误。

**恢复提示卷非空。** 它在保护已有数据。指定新的 Compose 项目名与未占用的网页端口；不要清空当前业务卷。恢复步骤见 [Docker 维护教程](DOCKER_RELEASE_GUIDE_ZH.md)。

## 模型服务配置与云端 API

| 错误 | 含义与检查 |
| --- | --- |
| 404 | 常见为 API 路径或协议错误；确认 Base URL 是否已经包含 `/v1`、`/api/v1` 或供应商专用路径，避免重复拼接。模型列表可访问不表示生成端点正确 |
| 401 / 403 | 密钥失效、权限或模型未开通；在自己的设置页核对账号与权限，不在 Issue 中发密钥 |
| 400 / 422 | 查看服务返回的参数诊断，核对模型名、画幅、时长、分辨率、参考数量与内容格式 |
| 余额或限流错误 | 检查供应商额度、并发和账单；不要自动换模型后仍冒充原方案 |
| URL 被安全策略拒绝 | 本地/私有服务需精确 origin 白名单，且必须是你拥有和控制的服务；不能把公网供应商地址误配置成任意私网代理 |
| 能测试连接但不能生成 | 连接、模型列表、权限、实际能力和计费推理是不同检查；从一个短镜头做真实生成 |
| 提交结果未知 | 保留任务、请求 ID 和供应商任务证据，先核对平台后台；不要反复新建同一付费任务 |

不同视频中转商可能使用完全不同的提交、查询、成功状态与结果 URL 结构。只有应用已实现对应适配器，才能切换使用。若协议尚未支持，应反馈已脱敏的官方接口文档，而不是将语言模型的聊天地址当作视频接口。

## 本地模型、GPU 与网络

容器的 `localhost` 是容器本身；Docker Desktop 宿主机通常用 `host.docker.internal`。远程 GPU 机用受控可达地址。检查服务实际监听、认证、防火墙及 `TRUSTED_LOCAL_SERVICE_ORIGINS` 精确白名单，配置修改后重新创建容器。

“下载了模型”不等于已启动服务。Windows 的 `E:\…` 路径、`.exe`、CUDA、原生 Python 环境不在 Linux 应用容器里。项目保留连接器并不等于对应模型已经容器化。Mac 的 Apple GPU 也不能运行 Windows CUDA 环境；当前没有 Mac 实机验证。

SeedVR2 / TTS 等若使用本机专用启动器，应按原生环境使用，或配置本项目实际支持的服务接口。不要通过在通用应用镜像里临时安装整套 GPU 依赖来掩盖部署边界。

## Word、人物、产品与提示词

- **导入字段缺失或映射错误：** 下载当前模板，保留表格结构与字段名，核对人物 ID、对白说话人、镜头时间与画幅；查看解析歧义后再启动。
- **找不到上传产品图的位置：** 项目工作台角色设置中，人物参考图下方是固定产品／道具参考区；上传和从图库选取均可选。
- **参考预算耗尽：** 查看当前模型已验证的图片数量和模式。人物、场景与产品共享同一模型预算；按程序修复建议重新安排有效输入或选择已验证服务，不能默默丢弃产品图。
- **提示词过长：** 在成片审核的完整提示词编辑区删减并保存后再提交。本地视频不使用应用层统一字符上限；云端遵守实际接口限制，仍保留必要身份和参考语义。
- **仅改文字画幅仍报宽高错误：** 真实尺寸必须与镜头画幅匹配；在制作画质或支持的修改输入中保存相应宽高/画幅，再生成新版本。
- **人物串脸或产品变样：** 核对选中的正式人物版本、参考图、包装版本、镜头绑定、站位与物品归属；技术合格不等于外观合格，人工审核后再合成。

## 配音与画质

**“TTS optional 未配置声音槽”。** 先核对这个镜头是否真的需要独立配音。需要 TTS 时，在开始制作前配置服务与该人物可用的授权声音参考；采用视频原生声音或无对白时，明确保存相应策略。Word 的声音描述不能自动提供参考音频。

**选择 SeedVR2 但无法派发。** 同时核对项目已保存的处理方式、视频超分路由、确切输出尺寸/画幅与已验证能力。某档位横屏成功不能证明竖屏和 4K 成功。准备与验证失败应显示真实原因，不应退回普通缩放冒充 AI 超分。当前 Windows 原生验证不能视为 Docker/Mac 推理支持。

**FFmpeg 找不到或媒体探测失败。** 通用镜像应已含工具，可检查：

```bash
docker compose exec backend ffmpeg -version
docker compose exec backend ffprobe -version
```

工具存在时再检查实际源文件、编码、权限与存储，而不是要求用户在宿主机重复装 FFmpeg。

## 合成和结果返回

**云端显示完成，程序无视频。** 查看本地任务是否已经下载文件、探测成功并建立可审核版本。云端返回成功文字或 URL 并不等于应用已经持久化 MP4。保留供应商任务 ID，检查 URL 可访问性、过期、下载错误与返回结构；不要直接重复生成。

**删除片段后渲染提示“选择已批准的真实版本”。** 检查当前合成轨道中剩余片段是否仍属于本项目，是否指向已批准而未删除的版本。刷新后仍能复现，请报告操作顺序、版本选择和请求 ID；不要修改数据库绕过验证。

**视频或最终 MP4 能下载却不能播放。** 检查文件是否真实媒体而非错误 JSON/HTML、时长与编码是否有效；后台媒体探测与前端播放器错误应分别记录。供应商返回帧数或音频时长略有不同，不应静默裁片，按明确编辑选择处理。

## 怎样提交可处理的 Bug

在 [仓库 Issues](https://github.com/willzhang35929924-ui/AI_Video_Creation/issues) 提供：系统/架构、Docker 与应用版本、是否云端或独立本地服务、最小复现步骤、期望/实际结果、脱敏错误码与请求 ID，以及必要的少量日志。用中性测试内容复现，避免上传私人剧本、脸图或声音。涉及凭据、越权或文件访问等安全问题，按 [安全说明](../SECURITY.md) 私下处理。
