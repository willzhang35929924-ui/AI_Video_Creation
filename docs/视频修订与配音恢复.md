# 视频修订、产品尺寸与原配音恢复

在“成片审核”选中具体视频版本，填写修改要求，先预览，再提交真实修订。原片和旧版本保持可访问。

“基于当前版本重新生成”先打开输入预览，确认后还需点击“提交真实修订”才派发模型。预览、提交或模型处理失败会在修改指令旁保留“修订未完成”与实际原因，修改要求不会丢失；核对原任务状态后再决定是否重试。

## 修改产品尺寸

使用剧本中的产品编号或已绑定的产品名称，写清一个最终目标，例如：

```text
P02 高3.5cm、宽5cm；其他产品保持原尺寸。
只调整P02的大小，人物身份、台词和原配音不变。
```

也可明确写“P02只有一个手掌大小”“P02只有两个手掌大小”或“P02只有水杯大小”。相对尺寸用于可见比例要求，不能作为真实厘米测量证明。多商品镜头要注明对应编号，系统不会把同一尺寸自动施加给所有商品。

本次明确尺寸会覆盖生成副本中冲突的旧道具尺寸；原剧本和覆盖回执保留。Context-IR 会将约束写入最终 H3 镜头正文并记录前后 SHA256，无法唯一绑定产品时会在采样前停止。本地 writer 的真实校验会检查目标商品的冲突尺寸、把印刷尺寸当实体比例，以及明确要求的首帧掌托、手脸同框、靠近脸颊动作。发现冲突后由原生 writer 最多修正两轮；最终正文仍冲突或退回 draft 时，H3 采样前停止，并保留原文、错误和校验回执。未识别的要求不会被推断为通过。输入约束保真不代表成片必然达到目标比例，仍需实际播放审核。

产品身份参考只选择同款商品。不同颜色或造型的款式、展示人物、包装印刷图不能仅凭同一个商品库名称合并为一个主体。本地 Qwen 会使用实际图片比较；混杂或不确定时，错误会指出对应图片编号。可以取消本镜不合适的引用，原图库文件无需删除。手持同款商品图片中的操作者保持为独立主体。

选择路径：项目工作台 → 角色设置 → 固定产品／道具参考图 → 产品图的制作引用（逐镜明确选择）。选中对应分镜，分别调整“用于视频”和“用于关键画面”，再保存。保存后重新预览新修订；旧视频显示的是它当时实际使用的参考，不会被当前选择改写。

实际派发会核对冻结输入的指纹、镜头归属、提示词、尺寸约束和参考素材；缺少快照或与实际请求不一致时，在上传和模型提交前明确停止。数据库中有快照不能替代模型请求中实际携带快照的验证。

明确写出的景别（例如“固定中景”或“固定中近景”）仅覆盖本次生成副本中的旧景别与运镜，原摄影资料保留在审计中；两种景别分别对应 Medium Shot 和 Medium Close-Up。“P02整体高度为人物脸部高度的一半”会作为独立的明确比例进入最终镜头正文，系统不会仅凭“水杯大小”推导半脸或厘米值。

## 画面修改后的配音与画质

对于对白、说话人和时长仍兼容的视觉修订，程序会冻结并校验原独立配音的来源、文本、角色和文件 SHA256。新视频返回后，任务继续显示“修订后处理”，依次完成需要的混音、口型和原画质处理，再创建待审的完整版本。

程序不会直接把旧视频整条原生声音复制到另一段动作上。若本次或历史修订已明确删除对白、改台词、静音，旧配音不会越过这些变更重新加回来。需要新对白时，先在“脚本与分镜”更新并通过项目工作台配音流程制作。

重启后沿已保存的子任务编号续接。后处理失败后重试只恢复相关处理，不再次请求视频模型；已提交且结果未知的外部任务需要先核对原任务，避免重复计费。

## 修复更新前已生成的原片

选中该历史修订，页面会读取“配音与画质恢复”诊断。若显示 **恢复此修订的配音与画质**，点击后使用这条已有原片补齐处理，不重新请求 H3。所需的配音来源、对白或文件有变化时会说明原因，不能用其他镜头的声音替代。

处理中的原片和中间版本可以查看、下载，但不能当作完整修订批准、发布或加入最终合成。完成后请在版本历史选择最新完整版本，重新审核其画面、声音、口型和产品比例。

最终合成保留的是时间线所选完整视频中的音轨，不会在导出时搜索旧版本补对白。因此应在审核阶段完成恢复。

## 应用与本地节点一起更新

应用源码更新后重新运行 `docker compose up -d`。本地推理主机也要更新仓库自带的 `VideoFactoryLocalVLMGuard` 节点，新节点要求 `production_contract` 与 `caller_contract_policy=revision_semantics_v2` 参数。仅更新网页容器不能替换推理主机上的节点代码；旧节点会被连接检查明确拒绝。

首次安装仍按[本地推理教程](local-inference.md)的 `install-nodes` 步骤操作。已有安装先备份 RuntimeRoot，等待全部队列空闲并停止对应 Comfy 服务；将旧的项目自有 `VideoFactoryLocalVLMGuard` 目录移到 RuntimeRoot 下的备份目录，再运行相同 `install-nodes --config ...` 命令。备份不要留在 `custom_nodes` 内，避免 Comfy 重复加载。其他项目自有节点若没有变化，安装器会核对后保留；不同内容不会被静默覆盖。

完成后运行 `check --config ...`，再按原管理方式启动 Comfy 与原生推理节点。此更新不下载模型，不修改第三方节点，不删除数据库、媒体、缓存或 Comfy 历史。

本地 Qwen 4B 的普通文本编译启用仅作用于新生成 token 的重复惩罚（1.1），EOS 不受惩罚；连续长段循环会以 `repetition_limit` 明确失败，不会截取残缺回复作为成功文本。结构化 JSON 继续使用原有约束。升级辅助模型脚本前先停止空闲的 Qwen 服务，再更新 Runtime bundle 并启动；启动后可在 `/health` 的 `prose_repetition_policy` 和实际回复回执中核对策略。源码变化后旧进程的 SHA 不匹配时，应按停止与升级顺序处理，不能放宽身份校验。

编译器会区分“包装图印有尺寸，但明确被当前要求覆盖”和“采用参考图尺寸”；首句中景构图里的当前掌托状态也可作为首帧证据。明确要求的完整商品、手掌与脸部同框仍必须写入实际镜头正文，摘要中的一句话不能替代。正文核验未通过时，审核页会显示具体缺失项，并保留本次要求、旧版本及配音；只有原生编译成功、真实出片和后处理完成后才创建完整待审版本。
